Ends the last Known limit ("server restarted by hand; no systemd/s6 unit") and delivers the README's promised install story. Owner decisions 2026-08-30: **Q1 B** service manager CLI + one-command `install.sh`; **Q2 C → Q3 A** `service update` (pull + build only what changed + restart) **and** scheduled auto-update fired by the dispatcher (cron in `wm_meta`, default daily 05:00 PKT, `--off` to disable), skipping when up to date, the tree is dirty, an update job is already running, or any WM run is `running`; detached updater with a 60 s `/api/health` check → Inbox row ("updated to <sha>" / needs-you on failure; rollback manual); **Q4 A** service runs as the installing user (root here), logs to the supervisor's native sink (s6-log dir / journald / log-file fallback), flags captured at install (`--host 0.0.0.0 --port 9010 --interval 20`), and this box cuts over now.

Facts that shape it: this box is s6 (`PID1 s6-svscan`, no systemd/cron); `/run/service` is a tmpfs scan dir (live registration via `s6-svscanctl -a`, wiped at boot) and `/etc/services.d/<name>/` is the boot-persistent legacy-services source (container overlay — survives restarts, not image recreation); Hermes registers its own `gateway-*` slots dynamically (`hermes_cli/container_boot.py`); owner rule: **detect the supervisor, never assume** (memory `no-docker-assumption`) — systemd → unit + `enable --now`, s6 → services.d + live register, neither → printed instructions incl. the nohup line. Restart drops browser terminals/chat streams; dispatched agent runs are separate processes (verify detachment in 8-1). `install.sh` requires `hermes` to be installed already (README premise) and refuses with pointers otherwise.
