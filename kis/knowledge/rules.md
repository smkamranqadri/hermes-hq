# hermes-hq — Working Rules
- Don't copy features from the three source projects without asking; `knowledge/project.md` lineage table is the allow-list.
- Real data only in the UI; empty/error states are honest, never faked.
- Owner-dependent questions are held, never guessed by agents.
- Prove work with real command output before marking done.
- Communication: short, lead with the decision, label choices A/B/C.
- Every list/detail page shows a content-shaped skeleton while loading and a spinner on busy buttons (`Skeleton`, `Btn busy`); applies to all future pages.
- Every new/changed page is checked at 390×844 with mobile emulation before done: tab bar clearance, safe areas, 16 px fields, `scrollWidth` 390 (missing `min-w-0` is the usual overflow cause).
- Owner changes to requirements must be edited into the task **description/DoD** — mid-run guidance (answer files, chat) does not bind the reviewer (learned 2026-09-02, task #138).
- **A code run that leaves its worktree dirty has not finished** (2026-09-07, engine-enforced in `record_completion`): `git status --porcelain` must be clean when a run reports done, or the run fails and the task returns to `rework` naming the uncommitted paths — bounded by `MAX_REWORK_CYCLES` so it parks on the owner's desk instead of re-dispatching forever. Gate on a DIRTY TREE only (a clean tree with no commits is a legitimate investigate/verify run), and the check FAILS OPEN on every error path. **Scoped to `is_code` runs** (owner decision 2026-09-07, task #205): a non-code run gets no worktree — `wm_dispatch` hands it the project's `primary_path`, the SHARED checkout — and has no branch to commit to, so gating it failed runs for dirt anyone else had left there (librarian run 465 was failed for an untracked harness directory it never touched, and its task began cycling toward the cap). Agents commit on their run branch and never merge to main; integration is a separate task. **Why it is in the engine and not just the brief:** 13 of 31 worktrees held work from runs marked done because nothing enforced it — a rule that lives only in a prompt eventually gets skipped.
- **The owner is the taxonomy authority, agents are not** (2b-ii): owner/import note writes auto-register their tags in `note_tag_taxonomy`; agent proposals may only use registered tags, and coinage must be declared (`new_tags` / `--new-tags`) and is registered *only* when the owner approves. Apply the same shape to any future agent-authored vocabulary (areas, note types).
- **Adding an agent profile includes refreshing the existing specialists' SOUL/MEMORY rosters in the same change** (learned 2026-09-06: the six older specialists predated the Librarian and none of their rosters listed it).
- **Anything an agent proposes or does that awaits the owner must be visible on EVERY surface the owner naturally lands on** — the list row, the detail page, AND the dedicated queue; a queue alone is not enough. (Learned 2026-09-06: three consecutive owner confusions over one librarian proposal that only the Review queue showed — fixed with the inbox `pending_proposal_id` chip and the note-page ProposalBanner. Apply the same test to future proposal kinds, lint findings, and run questions.)

- **The owner's answer file is append-only and the LAST line is authoritative** (2026-09-07, now in `_ask_owner_lines` so every brief carries it): agents must re-read the WHOLE file and act on the last line, because earlier lines may be stray taps or a choice the owner then changed, and a correction is always appended below what it corrects. Learned the hard way — run 466 quoted an earlier line and recorded an answer the owner never chose.
- **A decision the owner makes by tapping must never be sent by the tap itself.** Selecting is not sending: show the selection, require an explicit send, and leave a receipt saying what was delivered. (2026-09-07: single-choice option chips fired the POST on tap with no visible selection, so exploratory taps answered agents irreversibly — one run received `A,A,B,A,B,A` in 18 seconds.) Applies to any future control that commits an owner decision to an agent.
- **State never carries a volatile counter** (unread notifications, queue depths, run counts) — name the item that needs a decision instead. A number written into State is wrong within hours and reads as work that still exists; the live DB is the authority for counts. (Owner, 2026-09-07: "18 unread notifications" survived a sync after the owner had already cleared them.)

- Never assume hermes-hq runs inside the Hermes docker/s6 container (owner, 2026-08-29). Detect the platform (installed service vs. none) and fall back to owning the process; no hardcoded `/run/service`, `s6-svc`, `/opt/data` or container users in code.
