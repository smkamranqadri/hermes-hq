# hermes-hq — Technical Knowledge

## Architecture (decided 2026-08-29)
- **One Python service** (`backend` package, FastAPI; console script `hermes-hq`) that: contains the engine (`core/` = moved `wm_store`/`wm_dispatch`/`wm_run_agent`), runs the dispatcher as an in-process background loop (no Hermes cron), exposes REST (+ SSE for chat streaming; one WebSocket, the browser terminal), and serves the built React UI from `backend/static/`.
- **Frontend**: React 19 + Vite + Tailwind 4. Desktop top bar (glass, bordered): **Overview · Projects · Tasks · Agents · Chat**; right side **Tools** menu (Files · Terminal · Memory · Skills · MCP · Schedules), theme picker, bell, LIVE/PAUSED dot, SYSTEM. **Phones (<640 px, decided 2026-08-30)**: floating pill tab bar in the top nav's style (`TabBar.tsx`: Overview · Tasks · Chat · **Inbox** (unread badge) · More — Projects and Agents live under More (owner, 2026-08-30), safe-area aware, reserved height `--hq-tabbar`), top row = logo · LIVE + slots only (no bell on phones); `/inbox` (`pages/Inbox.tsx`) = the notification list + alert preferences; Agents, Tools, System, Appearance and Sign out live on `/more` (`pages/More.tsx`). Menus/sheets use the opaque `.hq-menu` surface; all form fields are ≥16 px on phones (iOS focus zoom). Reviews live inside Tasks + Task detail; Activity inside Overview feed + Project detail. (Supersedes the 7-tab IA in `hermes-work-manager/design/IA_FLOWS.md`; decided 2026-08-29.)
- **Theming**: all colors are `--hq-*` CSS vars per `[data-theme]` in `frontend/src/index.css`, exposed to Tailwind via `@theme inline`. Six fixed themes, no OS-follow: violet (default, WM tokens), nous, nous-light (only light theme, from workspace `claude-nous-light`), bronze, slate, hermes (palettes from hermes-workspace `styles.css`). Pref in `localStorage['hq-theme']`; `?theme=<id>` overrides (used for screenshots).
- **Fonts**: only Inter + JetBrains Mono bundled (`frontend/public/fonts`, no CDN, no `@fontsource`). One font choice: JetBrains Mono (default, everywhere), Inter, System Sans/Serif/Mono. Pref in `localStorage['hq-fonts']`; `?font=<id>` overrides. Why: the app renders on each viewer's device, so only bundled fonts look identical; owner wants JetBrains.
- **Shell style**: navbar anatomy from WM v0.9 (full-width glass bar, icon tile + `HERMES // HQ` wordmark + version pill, bordered pill-group nav, sysbar with TOOLS, appearance ◐, pulsing LIVE dot, clock, SYSTEM pill); `glass`/`glass-strong` card utilities; orb + dot-grid body background.
- **Data**: SQLite at `$HERMES_HOME/hermes-hq/hq.db`. One-time importer for legacy `/opt/data/work-manager/wm.db`.
- **Agents**: Hermes profiles, managed only via the `hermes profile` CLI. Roster templates ship in repo `agents/<name>/{agent.yaml,SOUL.md,skills/<name>-specialist/}` (extracted from the live profiles by `scripts/extract_agent_templates.py`; `agents/orchestrator` is an overlay for the default profile's SOUL). Add-agent flow (`backend/agents.py`): pick template → real `hermes profile create --no-alias --description` → layer SOUL + skill; fallback `ask-orchestrator` files a task. Never a custom profile-copy script.
- **Model/provider config** stays in Hermes; hermes-hq stores no API keys.
- **Ports**: hermes-hq default :9010 (legacy WM dashboard stays on :9009).
- **Install**: single command (`curl … | bash` or `pipx install hermes-hq && hermes-hq serve`) on a box with `hermes` on PATH.

## Status model
Engine keeps its precise state machine (`planned, waiting_approval, ready, running, needs_review, rework, blocked, failed, stalled, done, manual`; goals `draft/planning/planned/released`). UI shows 5 human states + reason line:
- **Backlog** = planned/draft
- **Queued** = ready, or dependency-gated (reason "waiting on #N")
- **Working** = running; `needs_review` shown as "Working · reviewer checking" (review is auto-dispatched to reviewer agent — verified `wm_store.py:1699`, `wm_dispatch.py:264`)
- **Needs you** = owner approval, blocked, failed, stalled — each with the one unblocking action
- **Done** = done, manual/archived

Auth `Authorization: Bearer <API_SERVER_KEY>`, loopback bind, port from `API_SERVER_PORT` (default 8642 = the default profile). hermes-hq assigns specialists 8650+ (analyst … reviewer) by appending `API_SERVER_PORT`/`API_SERVER_KEY` lines marked `# hermes-hq` to the profile `.env` when missing (Hermes has no allocator of its own).

Running = a real `GET /v1/models` probe. ## Auth + unblock rules (decided 2026-08-29)
Single password (`HERMES_HQ_PASSWORD`, else generated → serve log + `$HERMES_HQ_HOME/password`), cookie session, CSRF header on mutating requests, everything under `/api/*` behind login. Plain HTTP on LAN/Tailscale is accepted for a single owner; HTTPS is a reverse-proxy concern. Unblock semantics: `blocked` → primary action is owner feedback (→ `rework`, comment threaded into next brief); `failed`/`stalled` → `retry_task` (→ `ready`); `mark_manual` takes a task out of the queue. Writes only ever call `core.wm_store` functions; engine `ValueError` → HTTP 409 with the engine's message. `OWNER_FEEDBACK_SOURCE_STATUSES` includes blocked/failed/stalled, so a reply re-queues a stuck task as rework; the feedback is injected into the next brief even though the dispatcher claims (→ running) before rendering it.

## Engine rules carried over (non-negotiable)
- Every task belongs to a project with a valid `primary_path` (default `/opt/data/projects/<slug>`, root configurable).
- One persistent Hermes session per task run; session id must be deterministic, never "newest session".
- `planned` never auto-runs; completion only via `runs/<id>.completion.json` (exit code ≠ completion).
- Review = system-created review run (single-model), never a hand-made task; `changes_requested → rework → re-run → re-review` is the only rework path.
- Liveness = process state + Hermes session `last_activity_at` + timeout.

## Hermes gateway API (api_server platform)
- Auth: `Authorization: Bearer <API_SERVER_KEY>`; loopback bind by default; port from `API_SERVER_PORT` (default 8642).
- Session API: `GET/POST /api/sessions` (POST body `{id?|session_id?, title?}` → 201, id `api_<ts>_<hex>` when omitted; create-if-missing upsert), `GET /api/sessions/{id}`, `GET /api/sessions/{id}/messages`, `POST /api/sessions/{id}/chat` and `/chat/stream` (body `{"message": str|parts, "system_message"?}`), `POST /api/sessions/{id}/fork`, `POST /v1/runs/{run_id}/stop|steer`.
- `/chat/stream` is SSE `event: <name>\ndata: {json}\n\n`; names: `run.started`, `message.started`, `assistant.delta {delta}`, `tool.progress {tool_name,delta}` (reasoning), `tool.started|completed|failed {tool_name,preview,args}`, then completion; every payload carries `session_id`, `run_id`, `seq`, `ts`.
- Same SessionDB as the CLI: sessions created by `hermes chat` (dispatched runs, title `wm-run-<id>`) are readable/addressable through the gateway (verified 2026-08-29 on coder).
- `gateway.multiplex_profiles` (off here) would let the default gateway serve `/p/<profile>/…`; with it off, each profile needs its own gateway.

## Frontend build gotchas (learned 2026-08-29)
- Vite/Tailwind CSS minify keeps only the LAST of a prefixed/unprefixed pair: write `-webkit-backdrop-filter` before `backdrop-filter`, or Chrome (which ignores the `-webkit-` form) gets no blur.
- `overflow-x: hidden` on `html, body` makes body a scroll container and silently kills `position: sticky`; use `overflow-x: clip`.
- `npx tsc ... | tail` masks the exit code — chain with `&&` and no pipe when a failure must stop a commit.
- `hermes-hq` serves `index.html` with `Cache-Control: no-cache`; hashed assets are immutable, so a plain reload picks up new builds.

## Browser terminal (Group 6-1, 2026-08-30)
- `backend/terminal.py`: `WS /api/terminal/ws?session=&cols=&rows=` relays a real PTY (`pty.fork` → `bash -i`, `TERM=xterm-256color`). The shell runs as the **`hermes` user** (`HERMES_HQ_TERMINAL_USER`, uid/gid 10000): when `serve` runs as root the child drops privileges before `execve` and aborts if that fails; `HOME=/opt/data/home` (`HERMES_HQ_TERMINAL_HOME`), falling back to the passwd home when the dropped uid cannot enter it. `hermes` can read `/opt/data` and `config.yaml` but not root-owned trees (hq repo, `/opt/data/projects/*`) — accepted.
- Auth: `AuthMiddleware` (BaseHTTPMiddleware) never sees WebSocket handshakes, so the route checks the `hq_session` cookie + same-origin `Origin` itself and refuses at the handshake (browsers see 1006); "session gone" (4404) / limit (4429) are sent after `accept()` as `{t:"err"}` + close so the browser gets the code. The cookie is re-checked on every input frame → logout closes the shell (4401).
- Sessions: 1 MiB ring buffer replayed on reattach, detach TTL 30 min, max 8 live, reaper every 15 s, per-client output queue 512 chunks (oldest dropped), master fd non-blocking (input buffered ≤64 KB), close = SIGHUP → SIGKILL after 2 s (async). `GET /api/terminal/sessions`, `POST /api/terminal/spawn|{id}/close`. All PTYs are SIGKILLed on serve shutdown.
- Frontend: `components/terminal/{store,TerminalTab,TerminalHost}.tsx` (xterm 382 KB lazy chunk; main bundle unchanged). `TerminalHost` is mounted once in the app shell after the first open and never unmounted: full page on `/terminal`, Ctrl/Cmd+` bottom panel elsewhere on desktop (drag-resize, persisted height), hidden otherwise — xterm + sockets survive navigation. Tabs persist in `localStorage hq-terminal-tabs` with session ids (reattach after reload); theme from `--hq-*` vars (re-read on `data-theme` change); Ctrl+Shift+F find; phone = key row (Tab ^C Esc arrows ^D ^L Paste + 16 px input). JSX attribute strings keep backslashes literally — control bytes must be JS string literals (`d={'\x03'}`).

## Memory browser (Group 6-2, 2026-08-30)
- `backend/memory.py` (`/api/memory/*`). Profiles = orchestrator (root home) + every dir under the profiles dir. Files = `<home>/memories/{MEMORY.md,USER.md,*.md}` by allow-listed name (never a path). Hermes holds an **flock on `<file>.lock`** while it writes (the `.lock` files exist permanently, 0 bytes) → a write takes the same lock non-blocking and answers **423** while the agent holds it; stale mtime → **409** unless `force`; atomic temp+replace keeps the mode. Char limits come from the profile `config.yaml` → root `config.yaml` → Hermes defaults (2200 / 1375); `§` on its own line separates entries. Search is a plain case-insensitive scan over every profile (cap 200 hits). Reset unlinks MEMORY.md / USER.md.
- **Hermes bridge**: `scripts/hermes_bridge.py` runs under Hermes' venv (`<hermes root>/.venv/bin/python`, root derived from `wm_store.HERMES`, override `HERMES_HQ_HERMES_PY`/`HERMES_HQ_HERMES_ROOT`), cwd = the Hermes checkout, `HERMES_HOME` = the profile home; ops `providers | config | activate | setup | graph | node | limits`, JSON in/out (stdout is reserved for the result; Hermes' prints go to stderr). It calls Hermes' own dashboard internals (`hermes_cli.web_server._discover_memory_provider_statuses`, `_memory_provider_payload`, `_write_memory_provider_config_values` → secrets to the profile `.env`, `_require_memory_provider_ready` + `save_config` for `memory.provider`, `_install_memory_provider_setup`) and `agent.learning_graph.build_learning_graph` / `agent.learning_mutations.node_detail` — importing `web_server` costs ≈0.9 s, so provider lists are cached 120 s and graphs 30 s per profile (`?fresh=1` busts). Secret values are never returned (`is_set` only). Provider setup (pip/external installs) runs as a job.
- `backend/jobs.py` (`/api/jobs`, `/api/jobs/{id}`, `POST /api/jobs/{id}/stop`): detached subprocess (argv only, never a shell string) with an **allow-listed child env** (`jobs.child_env`: PATH/HOME/LANG/proxy vars + what the caller adds — never the server's own secrets, because provider manifests and hub install hooks run third-party commands), combined output in `<hq home>/jobs/<id>.log`, 30-min timeout (SIGKILL the process group), max 4 running (429), `status running|done|failed` (+ `timed_out`, `stopped`), `result` = the last log line that parses as a JSON object (a `{"ok": false}` result marks the job failed), `on_done` hook (used to drop server caches), all jobs stopped on serve shutdown. Shared by 6-3/6-4.
- Frontend `pages/Memory.tsx` (24 KB lazy chunk) with `?profile=&tab=files|providers|graph&file=&line=`; `components/AgentSwitcher.tsx` (`/api/memory/profiles`) and `components/editor.ts` (CodeMirror theme/highlight/lazy grammar shared with Files — pass `theme="none"` or `@uiw/react-codemirror` paints a light background). Graph = deterministic force layout in the page (no d3), forces scaled to the canvas; the canvas is measured once the graph box exists. Phone: file list in the bottom sheet, editor fills the card.

## Skills browser (Group 6-3, 2026-08-30)
- `backend/skills.py` (`/api/skills/*`). Everything except installs goes through the bridge, which calls **Hermes' own dashboard router handlers** in-process (`hermes_cli.web_routers.skills`: `get_skills` + per-skill SKILL.md frontmatter → tags/version/author/homepage/path/mtime, `get_skill_content`, `create_skill`/`update_skill_content` = `tools.skill_manager_tool._create_skill/_edit_skill` (frontmatter validation + security scan), `toggle_skill` = `skills.disabled` in the profile `config.yaml`, hub `list_skills_hub_sources | search_skills_hub | preview_skill_hub | scan_skill_hub`). Provenance hub|bundled|agent and usage counts are Hermes' (`skills/.hub/lock.json`, `.bundled_manifest`, `tools/skill_usage.py`).

## Hermes cron (facts, 2026-08-30)
- Hermes cron jobs fire from the **gateway's ticker** (`hermes cron status` → "Gateway is running — cron jobs will fire automatically"); a profile whose gateway is off never fires its jobs. `hermes [--profile p] cron tick` runs due jobs once and exits (how hq covers idle-stopped specialists). Jobs = agent prompt or script (`no_agent`) on a cron/interval schedule with delivery targets and a durable run history; dashboard router `hermes_cli/web_routers/cron.py`. Live: one active root job (04:00 UTC news brief) + the three paused legacy WM crons. Server clock is UTC; hq shows schedules in Asia/Karachi.

## Known limits (accepted for now)
- The server is restarted by hand after backend changes (`pkill -f 'hermes-hq serve'`, then the serve line in State); no systemd/s6 unit yet — belongs to the install work.

- Cookie session (`httponly, samesite=lax`, no `secure` flag) works over plain HTTP on the LAN and behind an HTTPS proxy; hermes-hq never terminates TLS itself (the owner uses `tailscale serve` on the Mac that hosts this OrbStack VM).

## Files API (Group 5, 2026-08-30) — `backend/files.py`
- Roots: `projects` = `WM_PROJECTS_ROOT` or `<hq home>/../projects` (`/opt/data/projects` live); `project:<slug>` = that project's `primary_path`. Nothing outside these two is reachable; every path is realpath-contained (absolute, `..`, symlink in any component → 403 "outside root"). Escaping symlinks are listed with `outside: true`, never followed.
- `GET /api/files/roots|list?root&path&hidden|read|raw?download=1`; `POST /api/files/write|mkdir|rename|delete|upload` (JSON except upload = multipart `root,path,files[]`). `read` returns `kind: text|image|pdf|binary`, `content` only for text ≤ 1 MB (`too_large` otherwise), plus `mtime`; `write` needs that `mtime` (409 "changed on disk" / "already exists" / "deleted on disk"; `force` overrides). Uploads ≤ 20 MB each, basename only. Writes are atomic through `tempfile.mkstemp` in the target folder.
- Rename/delete refuse (409) anything that is or contains a project's `primary_path`. `raw` serves html/xhtml/svg as attachment with `nosniff` + `CSP: sandbox` (no active content on the app origin); `raw?preview=1` serves html inline under `sandbox allow-scripts; connect-src 'none'` for the Files page's iframe preview (opaque origin: no cookies, no calls back to the app).
- `GET /api/project/{slug}/artifacts` = `result_paths` of the project's runs/tasks that exist on disk, with `inside_primary`/`rel` for the Files page. The old RO tree/preview readers were removed.
